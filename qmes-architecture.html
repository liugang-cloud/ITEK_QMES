通信协议

// 请求
{ "_id": 1697000000000.1234, "action": "接口名", "data": "入参（字符串或对象）", "token": "登录会话 token" }
// 响应
{ "success": true, "data": {}, "message": "错误信息", "_id": 1697000000000.1234 }
// 未登录 / 会话失效响应
{ "success": false, "code": "UNAUTHORIZED", "message": "登录已失效，请重新登录" }
  • HTTP 与 WebSocket 同端口 8080，HTTP 仅托管 web/ 静态文件。
  • 服务端原样回填 _id，前端 WsClient 据此把响应匹配到对应 Promise。
  • 前端用 Date.now() + Math.random() 生成 _id；断开后 3 秒自动重连，重连后凭 localStorage 中的 token 自动 checkSession 恢复会话。
  • 登录鉴权门：除 login 外所有接口必须携带有效 token（内存会话 Map，crypto.randomUUID 签发），否则返回 UNAUTHORIZED，前端收到后统一跳转登录页。
  • 操作人注入：创建 / 修改 / 导入类 action 的 create_by / update_by / inspector / operator 由服务端按当前登录用户名强制覆盖（OPERATOR_FIELDS 映射），不信任前端传值。
  • 调用日志：路由层在返回响应前统一调用 writeApiLog，把 action、用户、入参、结果、耗时写入 api_log；日志页通过 queryApiLogs 查询。
  • 直接发送纯字符串条码时，默认按 queryMaterial 处理（兼容旧客户端）。
  • 未知 action 返回 {success:false, message:'未知接口: xxx'}。
数据来源：http.js（54 个 action 分支，含登录鉴权门、操作人注入、调用日志）、server.js（57 个导出接口及其程序流程）、web/js/components.js（27 个组件）+ web/js/app.js（根实例，合计 28 个前端实例）、information_schema（15 张表）。
